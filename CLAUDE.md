# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`dai` — a Python CLI/TUI that makes two coding-agent CLIs argue about a task until they agree. A **solver** engine (default `claude`) does the work in the target directory with write access; a **critic** engine (default `codex`) reviews it read-only and pushes back; the solver rebuts each issue (FIXED / PARTIAL / REJECTED, with reasons). Rounds repeat until the referee calls consensus, deadlock, or a round/budget limit. Exit codes: 0 agreed · 1 did not agree · 2 error.

## Commands

Everything runs through uv (Python ≥ 3.11). `make help` lists all targets.

```bash
make install                    # uv sync — install deps (prod + dev)
make test                       # uv run pytest tests/ -v
make test-quick                 # uv run pytest -q
uv run pytest tests/test_orchestrator.py -k deadlock    # one file / pattern
uv run pytest tests/test_protocol.py::test_name          # one test
make doctor                     # check uv / claude / codex are on PATH
uv run dai "some task"          # run from the checkout (or: make run ARGS="'…'")
uv run dai -C ~/proj "task"     # run against another directory
uv build                        # wheel + sdist (make build); make install-cli installs globally
```

- The test suite is hermetic — no real agent CLIs, no network, no tokens spent. **`make smoke` is not**: it runs a real solver/critic argument in a sandbox and spends money. Don't run it casually.
- pytest works straight from the checkout without installing (`tests/conftest.py` prepends `src/` to `sys.path`). `asyncio_mode = "auto"`, so async test functions need no marker.
- No linter or formatter is configured.

## Architecture

Dependency direction: `__main__` / `tui` → `orchestrator` → `protocol`, `consensus`, `engines`, `budget` → `models`. `snapshot` and `transcript` are side-cars driven by the frontends, not by the debate.

**The loop** (`orchestrator.py`, class `Debate`): solve → critique → referee assessment → rebut → critique again. All non-consensus endings (deadlock, out of rounds, out of budget) funnel through the deadlock policy: `critic` means one final enforced turn where the solver applies the critic's open issues without rebuttal; `solver` means the work stands; `ask` defers to the TUI. `Debate` exposes `pause()/resume()/stop()/inject()` — the TUI's control surface — plus `abort_result()` for the TUI's kill path (`q` cancels the debate task outright instead of waiting for a turn boundary, then asks here for the ABORTED ledger to record). Injected user messages are prepended to the next turn's prompt and explicitly declared to outrank both agents.

**The contract** (`protocol.py`): JSON schemas force each side into a machine-checkable position (critic: verdict/issues/conceded/checked; solver: per-issue FIXED/PARTIAL/REJECTED). The prompts encode the anti-failure rules of a two-LLM loop, and price both sides the same — one artifact someone else can open. An approval must name the artifacts behind it: an APPROVE whose `checked` is empty is rejected, and the critic is asked once to show its work (`PROVE`, fired by `Debate._prove`) rather than the finding landing on the solver. A re-raised issue keeps its `claim` byte-stable so the referee can still see a stalled argument, and carries the new material in `evidence`. The solver may not mark FIXED anything it did not change this turn, and is told the two failures are one failure: agreeing to end the argument is a false report whichever role does it. **`rigor`** (`easy`/`standard`/`strict`/`brutal`, `rigor_rule`) modulates only how far the critic hunts and how hard the solver defends — never the evidence bar, since a level that waived it would be the rubber stamp this is here to remove. No `minItems` anywhere in the schemas: on `checked` it would make the empty array unreachable and disable the one mechanical guard, on `issues` it would demand a complaint every round, and codex's `--output-schema` does not accept it anyway. Parsing is forgiving about shape but strict about meaning: a missing verdict is never guessed (critic gets one format-retry; a solver report that isn't JSON falls back to raw text, since the work may exist on disk regardless), an unknown severity becomes `major`, an unparseable action becomes `REJECTED` — it must not read as agreement. Prompts also pin an explicit language rule because models drift languages mid-argument otherwise.

**The referee** (`consensus.py`, class `Referee`): stateful across rounds, because both failure modes — instant rubber-stamp agreement and an infinite loop of restated objections — are invisible in a single round. It fingerprints issue claims (ids are unreliable; models renumber) to detect a stalled open-set → deadlock after `no_progress_rounds`, flags approvals without evidence, flags unanswered repeats, and settles early when only `minor` issues remain (`stop_on_minor_only`).

`audit()` holds both approval rules and is deliberately side-effect free, because two callers ask it. `judge()` calls it **without** the solver, so only the hard rule can decide a round: an approval that says it checked nothing. `Debate._prove` calls it *with* the solver, adding the soft rule — an approval whose prose names none of the files the solver reported changing — because that one reads text and can be wrong: it may cost a turn (one re-ask per run, `Debate._challenged`), never the run. The orchestrator then guarantees the other half: a round that did not settle with no open issues ends as DEADLOCK rather than sending a write-access solver to "make the fixes" over an empty list, which is what used to happen.

**Engines** (`engines/`): the contract every engine must satisfy is NDJSON event stream + resumable session + JSON-schema-constrained final answer (`engines/base.py` docstring). `Engine` (ABC) owns all subprocess plumbing — spawn (`start_new_session=True`, so the CLI leads its own process group), chunked line reading (no `readline()` size limit), timeout, termination (SIGTERM→SIGKILL to the whole group via `killpg`, on timeout *and* on task cancellation) — and **never raises for agent-side failures**: they come back as `TurnResult.error` so one bad turn degrades the argument instead of killing the run. Subclasses implement `build_argv` + `handle_event` (+ optional `finalize`); register new engines in `ENGINES` in `engines/__init__.py`. One `Session` object per role, held by `Debate`, carries the session id across rounds so each agent keeps its conversation history and prompt cache.

Engine quirks are documented in each adapter's docstring (with observed stream shapes). Key ones:
- `claude.py`: schema passed inline (`--json-schema`), structured output arrives natively, session id is chosen up-front (`--session-id`) so it's addressable even if the first call dies. Access via `--permission-mode`.
- `codex.py`: schema via temp file (`wants_schema_file`); the structured answer arrives as message text and is recovered in `finalize()` via `parse_json_object`; multiple `agent_message` events arrive and **only the last is the answer** (earlier ones are narration); argv order is load-bearing (parent flags like `--sandbox`/`--model` must precede the `resume` subcommand); reports tokens but never cost. Access via `--sandbox`.

**Access control**: `models.Access` — solver gets WRITE (READ_ONLY under `--dry-run`), critic is always READ_ONLY. Enforced through per-engine CLI flags, with role-specific defaults in config (`solve_args` / `critic_args`).

**Money** (`budget.py`): claude reports measured cost; codex only tokens, so its cost is estimated from `[pricing.codex]` config — zero/absent prices mean *unknown, never free*, and the engine is surfaced as "unmeasured" in every report. `room_for_another_turn()` forecast-stops before an unaffordable round (mid-round cutoff leaves a half-modified tree); `resources_exhausted()` deliberately ignores the round limit so a deadlock resolution can still run its one enforced turn.

**Snapshots** (`snapshot.py`): a repo the agents change is *moved onto* `dai/<run-id>`, and each round lands there as an ordinary commit; the user is left standing on that branch (or, after `merge()`, on the branch it was rooted on). Repos nothing changed in are **not touched at all** — no branch, no commit, no switch — so `summary()` is built from `_switched`, not from `self.repos`.

**Neither the switch nor the commits go through `git checkout` or `git commit`.** Both rewrite files and run user hooks, and a formatter firing mid-round would edit the tree under the agents' feet. Instead: `commit-tree` from a throwaway `GIT_INDEX_FILE` tree, then `update-ref` → `symbolic-ref HEAD` → `read-tree`. `read-tree` without `-u` writes only the index, so **no file on disk is ever rewritten by dai and no hook of the user's fires** — that is the invariant that survived the redesign, and the one to keep.

Ordering inside `_capture_one` is load-bearing: observe → measure the tree → bail if unchanged → `_begin` (root the branch, minting `baseline` if needed) → commit → point → switch → `read-tree`. Nothing is created until something has actually changed, which is what keeps untouched repos untouched.

`observe()` runs at the round-1 gate and commits nothing: it is the only moment the user's WIP and the agents' work are still separable, so it records HEAD, the branch, and the working tree as `_baseline`. A late `_observe` (a caller that committed without gating) deliberately takes HEAD's tree instead — mislabelling the user's work as the agents' beats dropping the agents' work. `_begin` turns that baseline into a commit of its own when it differs from the base tip.

`_base_for` resolves both the root and the merge target — they are the same thing. `"default"` tries `origin/HEAD`, then `main`/`master`/`trunk`; a repo where the user is *ahead* of that branch falls back to where they stand, because rooting there would fold their commits into one `baseline` and carry them back on the merge. `git_ok()` exists for `merge-base --is-ancestor`, which answers with an exit code — `git()` reads stdout and cannot tell yes from no.

**A repo with anything staged is left alone**, once, with a note: a staged-then-edited blob lives only in the index, which `read-tree` overwrites, and snapshots record the working tree so it is in no commit of ours.

`refs/heads/dai/<run>` cannot coexist with a branch called `dai` (git stores refs as files), so `_point` falls back to a flat `dai-<run>` per repo — derived by `flat_name()`, which `branch_shapes()` also runs the prefix through (with the run id as a glob) so anything hunting for those branches cannot drift from what `_point` writes. `.dai/` is hidden via `.git/info/exclude` (not `.gitignore` — it must not appear in the user's diffs or commits).

**A branch name is not an address.** The workdir need not be the repo — it can hold several, or be no repo at all with all of them a level down — so a bare `git log HEAD..dai/<run>` typed there answers `fatal: not a git repository`, which reads exactly like "the run committed nothing". Everything user-facing therefore goes through `Snapshotter.summary() -> list[RepoResult]` (repo, branch, base, commits, merged, note), never a lone branch string: `transcript.render_report` renders `git -C <repo> …` per repo, `snapshot.describe()` is the one-line-per-repo form both frontends print, and `list_branches()` backs `dai --snapshots` (and `make snapshots`), counting commits by author `dai@localhost` rather than against HEAD so the count survives the user moving on or merging. `base` is recorded once per repo when the branch is rooted, because `HEAD..` stops being true the moment anything moves; rows are built from `_switched`, so a repo we never moved is absent entirely — untouched repos are not an address, and saying nothing about them is the honest answer now that they really are untouched. A repo we could not touch (broken git, something staged) surfaces through `report.skipped` instead.

**Merging** (`Snapshotter.merge()`, `[snapshot] merge`, `--merge`/`--ask-merge`/`--no-merge`): fast-forwards the base branch onto the run's tip and stands the user on it, again via `update-ref` + `symbolic-ref` (the index and tree already match the tip, so nothing is rewritten). The target is not a separate setting — it is whatever `_base_for` rooted the run on, so a fast-forward is possible by construction. It refuses (never raises; every refusal is a `note`, and the repo simply stays on `dai/<run>`) when the base branch moved underneath us, or the user moved off the run's branch. Fired only on `result.agreed`. The `baseline` commit carrying the user's own pre-run WIP lands on their branch too — hence the report prints `reset --hard <base>`. The TUI kill path never merges *unconditionally* — not merely because ABORTED isn't agreement: the debate can cross the line while the cancel is in flight, leaving a consensus result there.

**`merge` is a tri-state** (`config.Merge`: `NEVER`/`ASK`/`ALWAYS`), and **`ASK` is the default** — the merge writes to a branch of the user's, so the honest default is the one that cannot do that unasked. A bool in the file still means what it always did (`true`→`ALWAYS`, `false`→`NEVER`), because `_top_up` keys off key *presence* and will never revisit a config that already says `merge = true`. It is a `StrEnum`, which means **`if settings.merge:` is now a bug that reads as working code** — `Merge.NEVER` is a non-empty string. Every read is `is Merge.X` or `is not Merge.NEVER`.

The decision itself is `_settle_merge`, once per frontend (`__main__.py` and `tui/app.py`), sitting between `capture_final` and `transcript.finish` — after the commit so the rows are real, before the record so the report states what happened. `Snapshotter.preview() -> list[MergeCandidate]` is what makes "nothing is written until you choose" structural rather than a promise in a footer: it is read-only, and it hands both frontends every string and number they print, so neither touches git to draw the question. It gets its rows from `_refusal()` — hoisted out of `_merge_one` for exactly this — and one `git diff --numstat` from `base..branch`, deliberately including the user's `baseline` commit, because that is what the fast-forward actually carries. `merge(only=, kept=)` then moves the chosen ones; a repo left out is **still asked for its refusal first**, so one that was passed over because it *could not* go says so instead of "you kept the branch". `kept` is empty by default, which is what keeps "never asked" (`merge = false`) distinguishable in the record from "asked and declined". With no terminal to ask on, headless merges nothing and records that as the reason — the same way `deadlock_policy = "ask"` degrades with no `on_deadlock` wired.

**`MergeScreen`** (`tui/app.py`) is the fourth modal and the only one that lists things: a `RepoRow` per repo (`widgets.py`), each drawing both of its lines from one `Table.grid(expand=True)` so the counts reach the right edge at any width and line two crops where line one does — a row that wrapped to a third line would break the fixed height the cursor tint sits on. Its `_RowList` is `can_focus=False`, or a `tab` would hand `up`/`down` to the scroller; nothing on the screen is focusable and the cursor is the screen's own state. `repaint()` is a plain `refresh()` per cell and row, **not** `recompose` — that would take the cursor, the ticks and the scroll offset with it. `q` is bound to "keep the branches" so it is consumed: the app's `q` would cancel the very worker awaiting this screen (a modal already truncates the binding chain, so this is the guard that *says* so). `$dai-highlight` was added to the theme's `variables` for the cursor row — `Palette.highlight` existed but was reachable only as `block-cursor-background`, which names something else.

**The card is `height: auto` under a `max-height`, and that clamps it without making anything inside give way** — so past a certain terminal height the surplus was simply clipped, and what it clips is the bottom: the button, the way out, and the footnote promising nothing has been written. `MergeScreen._fit` (on `on_resize`, plus one `call_after_refresh` at mount) hands `#merge-rows` whatever height the rest of the card is not using, so the list is the only thing that shortens. It **measures** the chrome rather than counting it — a constant would be a number nobody remembers to change — and must add `styles.margin.height`, because `outer_size` covers border and padding but not margin, and three of those lines carry one. `overflow-y: auto` on the card is *not* an alternative: it is a no-op while the height is `auto`, since an auto-height box is by definition the size of its content. Breakpoints (`-short`/`-narrow`) fold away the lede, the footnote and the `esc` hint rather than cropping the question. Both controls in the action row carry the **same explicit width** — `auto` sizes each to its own label and an `fr` split has to give its remainder to one of them, so neither is even at every size; `min-width` has to be stated too, because `Button` ships 16 and the `Cell` beside it ships none.

**`--init` tops up an existing config** (`config.ensure_config` → `_top_up`): a file written a version ago is otherwise frozen, and its owner cannot discover options added since. Missing keys are inserted *inside* their existing section with their comments — appending a second `[snapshot]` would be a duplicate table and a parse error — and the user's values are never touched. `_table()` resolves dotted headers (`[engines.claude]`) against the nesting `tomllib` produces. `tomllib` only reads, and `textual` is the sole runtime dependency, so this is line-based on purpose rather than for want of a TOML writer.

**Transcripts** (`transcript.py`): append-only `.dai/runs/<run-id>/events.jsonl` written as the run happens, plus `report.md` at the end; `--runs` / `--show` read these. A read-only workspace silently disables recording rather than stopping the run. `snapshots()` says nothing for a round that changed nothing, which for a whole run that changed nothing would leave no trace of the branches at all — hence the `branches` event `finish()` always writes. Order at the end of a run is load-bearing: `capture_final` → `snapshots()` → `merge()` → `finish(repos=summary())` → display, so the report can state what the merge did (and print its undo, `reset --hard <base>`) instead of telling the user to adopt work they already have. In the TUI the display happens *after* `app.run()` returns (`__main__._where`), because Textual draws on the alternate screen and wipes it on exit — the scrollback is the only surface that survives. `DaiApp._settled` guards `action_stop_debate` for the same reason `result` cannot: `result` is set before the final commit, the merge and the transcript, and exiting in that window loses all three.

**Frontends**: `__main__.py` wires config → engines → `Debate`, then picks headless streaming (non-TTY or `--no-tui`) or the Textual TUI (`tui/app.py`). Both attach the same four `Debate` callbacks (`on_event`, `on_agent_event`, `on_round_start` for the per-round commit, `on_deadlock`). The TUI runs the debate as a Textual worker on the app's own event loop, so callbacks touch widgets directly.

`tui/theme.py` owns the look: two `Palette`s (`DARK`/`LIGHT`) and the Textual `Theme` built from each, registered and selected in each app's `__init__`, not `on_mount` — the stylesheet is parsed before mount. Nothing in it is a constant: `theme.MUTED` and `theme.S_ERROR` go through a module `__getattr__` and resolve against the *active* palette on every access, so a mid-run theme change reaches everything that reads a colour at render time. Two consequences: nothing outside the module may store a resolved colour (log lines store a style *name* and call `style()` when they draw — that is what `AgentPane`/`VerdictLog`'s `_Line`/`_Entry` recipes are for, since a `RichLog` keeps rendered strips that no Textual API will re-render), and inside the module a bare `MUTED` is a `NameError`, so the helpers call `color()`. It also holds the helpers for things a terminal cannot style (`spaced` for letterspacing, `keycap`/`hint` for key rows, `meter` for the round bar).

`tui/appearance.py` decides which palette that is. `detect()` asks the terminal with OSC 11 before the first frame is drawn (a palette chosen later is a flash of the wrong one), falling back to `COLORFGBG` and then to dark. `AppearanceDriver` — Textual's `LinuxDriver` with our parser lent to its input loop — turns on mode 2031 so the terminal reports scheme changes, and `SchemeParser` takes those reports, and any late OSC 11 answer, out of the input stream: Textual reissues escape sequences it does not recognise as literal keypresses, so anything left in would be typed into whatever has focus. It holds back a cut-off sequence across reads but never a bare `\x1b`, which is the escape key. A terminal that does not support mode 2031 simply never reports, and the palette stays as it was found. `App.watch_theme` (in the `FollowsTerminal` mixin) then repaints, after Textual's own CSS refresh, which it is guaranteed to follow because both are queued with `call_next`. `tui/completion.py` implements the `@` path picker; it inserts a plain relative path — the `@` never reaches the agents (codex has no `@`-syntax and both sides must receive identical text). Its `PromptArea` is a `TextArea` wearing an `Input`'s `value`/`cursor_position` surface, so the mention logic stayed put; `Enter` commits and `shift+enter`/`ctrl+j`/`alt+enter` break the line, all intercepted in `_on_key` because a `TextArea` swallows `enter` and the arrows before bindings run.

## Conventions and gotchas

- **Adding a config option means touching several places in step**: the `Config` dataclass, `from_dict()` fallbacks, and `DEFAULT_CONFIG_TEXT` (the annotated file `--init` writes) in `config.py` — plus `build_parser()` and `_apply_overrides()` in `__main__.py` if it's flag-overridable. `[snapshot] merge` is the most recent and the most complete worked example: `Merge` + `_merge()` in `config.py`, three flags in `build_parser()`, and the precedence in `_apply_overrides()`. It also shows the two things that make one of these awkward — it must keep accepting the bool it used to be, and it needs a different fallback per frontend. `[critique] rigor` / `--rigor` is the simpler one, including the `_rigor()` fallback: an unrecognised value in the file is read as the default rather than raised over, while the flag refuses it outright. Note the shape both share — a typo costs the run its automation, never the run.
- **Testing approach — three layers, no real CLIs anywhere**: engine adapters are replayed end-to-end with `cat` streaming captured real CLI output (`tests/fixtures/*.jsonl`) through the genuine `Engine.run()` plumbing; the orchestrator/referee are driven by the `Scripted` engine returning canned structured payloads (`test_orchestrator.py`, imported by `test_tui.py`); the TUI is driven headlessly with Textual's `run_test()` pilot. New stream-parsing behaviour should come with a captured fixture.
- **`tui/styles.tcss` declares no colours at all**, `$dai-*` included: they come from the theme's `variables`, which is the only way they can change with it. A `$var:` in the source is *appended* to the theme's value rather than replacing it, which looks like an override for a single colour and silently corrupts anything longer (`$dai-solver 35%`). A bare host that loads the sheet — `PaneHost` in `tests/test_tui.py`, `Harness` in `tests/test_completion.py` — has to call `apply_theme()` first.
- **Nothing may capture a colour at import time.** A module-level `{Severity.MAJOR: theme.S_WARNING}` freezes the palette when the module loads and never follows a theme change; the severity, phase and outcome tables hold *names* and resolve on use. Same for default arguments — `AgentPane` takes a role, not an accent.
- **`RichLog` is constructed with `min_width=1`** in the panes and the verdict log. The stock 78 renders every line 78 columns wide and lets the widget clip it, which in a half-width pane silently eats the tail of every sentence instead of wrapping it.
- Errors degrade, never crash: engine failure → `TurnResult.error`; unwritable transcript → disables itself; per-repo snapshot failure → a "skipped" note. Keep this property when extending.
- `make help` is generated from the `## ` comments on Makefile targets; the README points at `make help` rather than repeating the list, so a new target needs only its `## ` comment. The README does still spell out flags by example — keep those in step with `build_parser()`.
